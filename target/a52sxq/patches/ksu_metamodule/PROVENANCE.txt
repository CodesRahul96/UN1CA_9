What it does on this phone (5.4 kernel, erofs system/vendor/product/odm):
  - install (customize.sh, run by ksud): picks the aarch64 binary, creates a sparse 2 GB ext4 image modules.img
    (mke2fs -O ^has_journal) in /data/adb/modules/meta-overlayfs.
  - metainstall.sh (sourced by ksud for every later module install): copies the module's system/ vendor/ ...
    into the image (labels copied), the module itself stays in /data/adb/modules/<id>.
  - metamount.sh (ksud post-fs-data, after all post-fs-data scripts, before init's /system/etc/init post-fs-data
    actions such as k4-gpu-driver): loop-mounts the image and overlays /system, /vendor, /product, /odm with the
    enabled modules' content as lower layers (source "KSU", so KernelSU's umount feature recognises the mounts);
    child mounts are re-bound. Needs CONFIG_OVERLAY_FS, CONFIG_BLK_DEV_LOOP, CONFIG_EXT4_FS: all =y in the
    bone-machine 5.4.302 kernel (/proc/config.gz). erofs lower layers are fine (overlayfs only needs an upper/work
    dir on a writable fs, which it does not use here unless /data/adb/modules/.rw exists).
  - post-mount.sh: ksud kernel nuke-ext4-sysfs (supported by this ksud).
  A module installed before the metamodule (none yet, or another one such as Mountify) is not in the image:
  k4-ksu-metamodule copies it in at boot_completed the way metainstall.sh would (same conditions, cp -af under
  ksud's busybox, metainstall.sh's own label functions), so it is mounted from the next boot on; no reinstall.
  - hide from ordinary apps (k4-ksu-metamodule, boot_completed): the ext4 image mount on
    /data/adb/modules/meta-overlayfs/mnt is a /data/adb line in every /proc/<pid>/mountinfo (what Native Detector /
    banking apps flag, "Suspicious Mount"), and whenever a module overlays a partition that partition's overlay line
    carries lowerdir=/data/adb/modules/.../mnt/<id>/... ("KSU/AP modules.img"); the image also makes a
    /proc/fs/ext4/<loop> entry, which the image's post-mount.sh drops (ksud kernel nuke-ext4-sysfs). ReSukiSU already
    umounts module mounts per non-root app (ksu_uid_should_umount, default on), which hides those lines and gives the
    app the stock partition - but only for mount points on its umount list and only after the kernel is told modules
    are mounted. On a metamodule ROM ksud mounts no module itself, so it never notifies (ksu_module_mounted stays
    false) and the list stays empty: the per-app umount was dead and every app saw everything. The hook now, every
    boot, adds the image mount point and each live "KSU" overlay mount point (read from mountinfo, so only partitions
    actually overlaid) to the kernel umount list and notifies the kernel (ksud kernel umount add / notify-module-
    mounted). Non-root apps then see the stock partitions; the shell and su-granted apps keep the modules. Not a
    detach (umount -l would hide the image from root too, but a later module install re-mounts it - a second ext4
    superblock on one backing file while overlayfs pins the first, which can corrupt the image). ROM-side (hook)
    change only; the shipped zip is unchanged (still 1.3.1-k4.1, versionCode 13101), so there is no in-place
    metamodule update. No susfs on this kernel (CONFIG_KSU_SUSFS off), so a su-granted app or a process not covered by
    the per-app umount still sees the mounts - a generic KernelSU trait, not hideable here without kernel changes.

Alternatives looked at (all metamodules in the official KernelSU-Modules-Repo org):
  - meta-mm (Magic Mount, 7a72) v1.0.1-sprout: GitHub repo is a placeholder, its sourceUrl
    codeberg.org/ovo/meta-magic_mount is gone (404): no source for a GPL-3.0 binary, cannot be redistributed.
  - magic_mount_rs v4.0.2 (Apache-2.0): its mount binary dlopens libs/arm64-v8a/libchecker.so, a 2.4 MB Go blob
    without source in the repo, to verify a signature of the module and panics if that fails - an opaque binary in
    the boot path.
  - hybrid_mount v6.2.0 (Apache-2.0): three mount engines (OverlayFS, magic mount, Kasumi), 3.4 MB, web UI: far
    more than "mount the modules", more to go wrong in a default.

K4 changes (meta-overlayfs-k4/K4_CHANGES.txt; each changed script says what changed, look for "K4"):
  Found on 9.3.81 (2026-10-24): with the unmodified 1.3.1 the phone bootlooped into recovery after an Adreno V@0849
  driver module (no customize.sh) was installed through it. KernelSU's installer labels everything under
  system/vendor vendor_file, metainstall.sh copies those labels into the image, so /vendor/lib64/egl/*.so (and the
  merged lib64/hw and firmware directories) were vendor_file over /vendor; SurfaceFlinger may only read
  same_process_hal_file there ("avc: denied { read } ... name=libEGL_adreno.so dev=overlay ... vendor_file"),
  libEGL aborted it on every start ("couldn't find an OpenGL ES implementation"), and Samsung's bootchecker
  rebooted ("Infinite reset happened ... count: 5") until recovery. Evidence: /mnt/B1/OneUi9/scratch/bootfail_9381/
  phone/ksulog/{dmesg,logcat}.old.log (ksud's capture of the failing boot); the image copy on the phone had every
  file and directory vendor_file and its mnt/ directories unlabeled.
  1. metainstall.sh: set_perm got a mode in its SELinux-context argument (set_perm <dir> 0 0 0755 0644), which
     printed "chcon: invalid context: 0644" on every install and left mnt/ and mnt/<id> unlabeled.
  2. metainstall.sh: on a ROM with /system/bin/k4-gpu-driver, a module carrying an Adreno set
     ({vendor,system/vendor}/{lib64,lib}/egl/libGLESv2_adreno.so) is not copied into the image; the GPU driver
     selector imports it with the stock labels, its allowlist and a trial boot (also the first boot after the
     install). metamount.sh removes such a module's copy that an earlier install left in the image.
  3. metainstall.sh: a module directory that also exists on the partition gets that directory's label (an
     overlayfs merged directory shows the topmost layer's label: the module's lib64/hw hid the stock
     vendor_hal_file one, /vendor/etc the vendor_configs_file one). Files keep the module's labels.
  4. metamount.sh: the image copy of an uninstalled module is removed (metauninstall.sh runs before the image is
     mounted and skips it; a reinstall of the same id then also mounted the old version's leftover files).
  k4-ksu-metamodule updates an installed meta-overlayfs with a lower versionCode (the unmodified 13100, installed
  by 9.3.81) to this build in place, and completes a fresh install at once (no pending state: ksud blocks every
  module install while a metamodule is pending, "Installation Blocked ... Reboot to apply changes first").
